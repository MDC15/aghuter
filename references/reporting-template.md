# Human-readable execution report

Use this compact structure after a multi-step task:

## Result
One sentence stating what was achieved.

## Actions
- Action — purpose — outcome.

## Verification
- **Passed:** checks that completed successfully.
- **Failed:** checks that ran and failed, with the key reason.
- **Skipped:** checks not run and why.
- **Inconclusive:** checks whose result could not be established.

## Changes
List important paths changed; state explicitly when no files were changed.

## Approval needed
Name the exact external, destructive, costly, or irreversible action and its target. Do not use vague requests such as “May I proceed?” when the concrete action can be stated.
